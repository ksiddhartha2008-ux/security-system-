# Frontend architecture

## Stack

- React 19.3, TypeScript 5.7, Vite 6.4.
- React Router 7 with `BrowserRouter`.
- Tailwind CSS 4 plus the application stylesheet.
- Astryx 0.7.13 for the shell, theme, badges, inputs and layout primitives.
- Lucide icons.
- Hand-built SVG charts. No chart library.

## Layer diagram

```
main.tsx
  -> App.tsx
       BrowserRouter
         AstryxProviders            Theme(secureflow, dark) + LinkProvider
           AuthProvider             session, role, permissions, features
             Suspense               route chunk fallback
               Routes
                 public pages       landing, login, signup, terms, privacy
                 RequireAuth        redirects to /login
                   AppShellLayout   AppShell + TopNav + SideNav + <Outlet/>
                 lazy page chunks   one per module
```

## Application shell

`components/layout.tsx` exports `AppShellLayout`, `PageHeader` and `RequireAuth`.

- `AppShell` owns the skip link, the main landmark, the top bar and the mobile navigation drawer.
- `TopNav` holds the product name, workspace name, demo indicator, simulation action and account menu.
- `SideNav` groups destinations exactly as before: Operations, Response, Exposure, Programme, Workspace. It sets `aria-current` on the active route and shows the live incident and detection counts.
- The website item is hidden when the website protection flag is off.
- The shell keeps a Server-Sent Events subscription for the live indicator.
- Page titles are rendered by `PageHeader` inside each page, not by the shell.

## Data flow

`lib/api.ts` is the only HTTP boundary.

- It sends `credentials: 'same-origin'`.
- It reads the readable `sf_csrf` cookie and sends `x-csrf-token` on every non-GET request.
- It parses the `{ data, meta }` envelope and throws `ApiError` with the server code and request id.
- It never stores a bearer token, API key or password in browser storage.

`lib/auth.tsx` loads `/auth/me`, keeps the user, organization, permissions and feature flags, and exposes login, register, logout and refresh. Route guards are a convenience only; the API enforces every authorization decision.

`lib/hooks.ts` provides `useApi`, `useDebounced`, `useToasts` and `useEventStream`. Pages own their filters and page numbers; the server owns filtering, pagination and ordering.

## Styling

`styles.css` is the single global stylesheet.

1. Declares the cascade layer order.
2. Imports Tailwind, the Astryx reset, the Astryx component CSS and the generated SecureFlow theme.
3. Defines the legacy Tailwind theme tokens used by existing pages.
4. Defines application classes: shell, cards, tables, forms, badges, dialogs, charts and responsive rules.

The Astryx theme lives in `lib/theme/`. `secureflowTheme.ts` is source; the other files are generated by `npm run theme:build` and checked by `npm run check:theme`.

## Performance choices

- Route-level code splitting for every module and public page.
- No virtualization: the largest page is paginated server-side at 25 rows by default, so a DOM windowing library is not justified.
- Charts are small SVG components fed by API series. No chart dependency is loaded.
- Astryx components are imported from their subpaths, not from a barrel.
- The Astryx CSS is precompiled and cached by the browser. It is larger than the old stylesheet; this is the main cost of the design system and is recorded in the integration report.
- Fonts are system fonts. No webfont request is made.

## Build and test commands

```powershell
npm --prefix frontend run typecheck
npm --prefix frontend run build
npm --prefix frontend run check:theme
npm test                  # backend and integration tests
```

There is no frontend unit-test runner configured in this repository. UI checks are manual browser passes plus the DOM accessibility audit in `docs/ACCESSIBILITY.md`; backend integration tests cover the APIs the pages consume.
