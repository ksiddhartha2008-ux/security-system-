## PLAN

Walk the full owner workflow in the built application at a narrow viewport, confirm that every step is server driven and survives a reload, and check the production build.

## CALL

Server:

```powershell
$env:SF_WEBSITE_PROTECTION='true'
$env:SF_ALLOW_TEST_HOSTNAMES='true'
$env:SF_DNS_FAKE_FILE='backend/data/demo-dns.json'
npm start
```

Browser: `http://localhost:4000`, 424 px wide viewport.

```powershell
npm run typecheck
npm run build
```

## PAUSE

Walkthrough, in order:

1. Navigation shows **Websites** under Operations for an admin. An analyst sees the list but no write actions.
2. `/websites` shows four counters, an empty state and **Add website**.
3. `/websites/new` previews `demo-shop.example.test` and `example.test` before submit. The scope explanation changes with the selected scope.
4. Submitting creates a pending website. The page shows the TXT record name, relative name, value, TTL, the keep-the-record sentence and the expiry countdown.
5. Publishing the value in the file resolver and pressing **Verify now** changes the site to **Verified**, creates the asset and shows the install snippet.
6. **Keys**, **Create key** opens the label dialog, then the step-up dialog. After the password the secret is shown once with a copy button and a required acknowledgement. Closing it leaves only `sfk_<key id>_…<last4>`.
7. Sending 26 events for the site changes the connection to **Connected**, shows **Detections (2)** and **Incidents (1)**.
8. The incidents tab shows `INC-2026-1009`, P2, status Open. The detections tab shows `W-AUTH-001` (high, risk 82) and `W-AUTH-003` (critical, risk 100) with their factors.
9. The page is usable at 424 px: tables scroll inside their card, the page itself does not scroll sideways.

## INTEGRATE

Every step persisted on the server: a reload kept the site, the challenge, the key metadata and the connection state. The wizard is not a client-side state machine. The copy shows no invented numbers and no marketing claims.

## ACT

The first walkthrough used an analyst session, so the create action was correctly absent. After signing in as an admin the full flow worked. The incident title bug found in step 8 was fixed in `60e02c8`.

## RECORD
