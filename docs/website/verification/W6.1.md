## PLAN

Attack the feature from a second organization and from an unauthenticated client, confirm audit atomicity, run the repository secret scan, and record what is not covered.

## CALL

```powershell
cd backend
node --test --test-name-pattern "another organization" tests/website-api.test.mjs
node --test --test-name-pattern "revocation" tests/website-api.test.mjs
node --test --test-name-pattern "failed business change" tests/website-scheduler.test.mjs
npm run scan:secrets
```

## PAUSE

```text
✔ another organization cannot read, change or verify the website
✔ revocation takes effect immediately and the audit chain stays valid
✔ a failed business change rolls back its audit entry
Secret scan clean: no website key, private key block or AWS access key id found.
```

Second organization attempts, all refused with `404`:

- read detail, update name, run verification
- list keys, revoke a key, delete the website
- read events, detections, incidents
- list websites (empty)
- register the same hostname (`409 site_conflict`)

Audit checks:

- `GET /settings/audit-logs/verify` returns `ok: true`.
- Actions include `website.created`, `website.verified`, `website.key_created`, `website.key_revoked`, `website.data_deleted`.
- The serialized audit response contains neither the full key nor the challenge value.

## INTEGRATE

Tenant scoping is applied in every query through `getSite`, `activeKeyCount` and the route filters. No route accepts an organization id from the client. The audit helper throws on failure, and the rollback test proves the audit row disappears with the business change.

## ACT

No security defect was found by these tests. One product defect (incident title) was found in the UI walkthrough and fixed separately.

## RECORD

W9 is VERIFIED for the tested cases.

## Security second pass

Five ways the control could still fail, and the outcome:

1. **Timing oracle on key ids.** Unknown ids take the constant comparison path, but no timing measurement exists. Residual.
2. **Concurrent key creation over the limit.** Creation is serialised and re-counts. Reviewed, not load tested.
3. **DNS spoofing.** Not mitigated. Two resolver corroboration is not implemented. Residual.
4. **Stored XSS in event fields.** React escapes by default and the new pages do not use `dangerouslySetInnerHTML`. A hostile path was stored and read in the walkthrough. No automated payload suite.
5. **Cross-tenant data in export.** Export is built from queries filtered by `org_id` and the site id, and the test asserts no key material. A second organization cannot call it because the site lookup returns 404.

## Accepted risks

- G1 is blocked: no email verification.
- The in-process session limiter is single node.
- No independent penetration test has been performed.
