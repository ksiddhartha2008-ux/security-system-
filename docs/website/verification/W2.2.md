## PLAN

Exercise the ingestion endpoint with cookies, query keys, wrong content types, unknown fields, prototype pollution, oversized bodies, invalid events, duplicate ids, replay and per-key rate limits.

## CALL

```powershell
cd backend
node --test --test-name-pattern "ingestion" tests/website-api.test.mjs
node --test --test-name-pattern "duplicate ids" tests/website-api.test.mjs
node --test --test-name-pattern "real batch" tests/website-api.test.mjs
```

## PAUSE

```text
✔ ingestion refuses cookies, query string keys and invalid envelopes
✔ duplicate ids inside one batch are counted, not stored twice
✔ a real batch produces one detection, one incident and is idempotent on replay
✔ ingestion limits, sensitive attributes and control characters
```

Observed responses:

- Cookie session only, no bearer: `401 invalid_api_key`.
- Key in `?api_key=`: `401`.
- `text/plain`: `415 unsupported_media_type`.
- Unknown envelope field: `400 invalid_batch`.
- `__proto__` in the envelope: `400 invalid_batch`.
- 101 events: `400 invalid_batch`.
- Four invalid events: `202` with codes `unknown_event_type`, `timestamp_out_of_range`, `host_mismatch`, `missing_field`.
- 300 KiB body: `413 payload_too_large`.
- 25 failures: `202 accepted 25`; replay: `accepted 0, duplicates 25`.
- Same event id twice in one batch: `accepted 1, duplicates 1`.
- Six batches of 100: accepted; the next request: `429 rate_limited` with `Retry-After`.
- Attribute named like a credential: `dropped_fields 1` and absent from storage.
- Control character in an actor id: `invalid_actor`.

## INTEGRATE

All pass criteria met. Events are stored before detection runs. The pipeline job row is written before the response, so a crash does not lose stored events.

## ACT

The first smoke request used the wrong base path (`/v1/ingest` instead of `/api/v1/ingest`) and received Express's HTML 404. The script was corrected; the route itself was already mounted correctly.

## RECORD

W2.2 is VERIFIED.

## Notes

- Body limit 256 KiB is enforced by `express.raw` while reading, before JSON parsing.
- The route is mounted before cookie parsing, so `requireCsrf` cannot apply and cookies cannot authenticate.
- Detections run in `setImmediate` after the `202`. Tests poll the detection endpoint, which also proves the asynchronous path works.
